# Решение задачи о покрытии множества с помощью коэффициента Жаккара.

## Определения

### Задача о покрытии множества (Set Cover Problem)

Задано конечное множество $U$ (универсум) и семейство его подмножеств $S = \{S_1, S_2, \dots, S_m\}$, причём $\bigcup_{i=1}^{m} S_i = U$.

Требуется найти подсемейство $C \subseteq S$ наименьшей мощности, покрывающее универсум:

$$
|C| \to \min, \qquad C \subseteq S, \qquad \bigcup_{S_i \in C} S_i = U
$$

### Коэффициент Жаккара

Коэффициент Жаккара — метрика для сравнения похожести двух множеств:

$$
J(A, B) = \frac{|A \cap B|}{|A \cup B|} = \frac{|A \cap B|}{|A| + |B| - |A \cap B|}
$$

## Алгоритмы решения

### Жадный алгоритм

На каждом шаге выбирается подмножество, которое покрывает больше всего ещё не покрытых элементов.

```text
GREEDY-ALGORITHM(U, S):

    uncovered = U #непокрытые элементы
    cover = ∅ #выбранные подмножества

    while uncovered ≠ ∅:
        S_best = argmax_i |S_i ∩ uncovered| #подмножество, покрывающее больше всего непокрытых элементов

        if |S_best ∩ uncovered| = 0: #покрыть остаток невозможно
            return cover, uncovered

        cover += {S_best}
        uncovered = uncovered \ S_best

    return cover, uncovered
```

### Почему жадный алгоритм не всегда находит оптимум

Самое большое подмножество может покрыть часть элементов так, что оставшиеся элементы придётся покрывать большим числом подмножеств.

Пример, когда жадный алгоритм выдаёт неоптимальный вариант:

- $U = \{1, 2, 3, 4, 5, 6, 7, 8\}$
- $S_1 = \{1, 2, 3, 5, 6\}$, $S_2 = \{1, 2, 3, 4\}$, $S_3 = \{5, 6, 7, 8\}$

Ход жадного алгоритма ($R_t$ — множество непокрытых элементов после шага $t$, $R_0 = U$):

| Шаг $t$ | Выбрано $S_{i_t}$ | Выигрыш $\lvert S_{i_t} \cap R_{t-1} \rvert$ | Осталось $R_t$ |
|---------|-------------------|----------------------------------------------|----------------|
| 1 | $S_1 = \{1, 2, 3, 5, 6\}$ | 5 | $\{4, 7, 8\}$ |
| 2 | $S_3 = \{5, 6, 7, 8\}$ | 2 | $\{4\}$ |
| 3 | $S_2 = \{1, 2, 3, 4\}$ | 1 | $\varnothing$ |

Жадный алгоритм возвращает $C_{\text{greedy}} = \{S_1, S_3, S_2\}$, то есть $|C_{\text{greedy}}| = 3$.

Оптимальное решение:

$$
C^{\ast} = \{S_2, S_3\}, \qquad S_2 \cup S_3 = \{1, 2, 3, 4\} \cup \{5, 6, 7, 8\} = U, \qquad |C^{\ast}| = 2
$$

На первом шаге $S_1$ выигрывает у $S_2$ и $S_3$ (5 элементов против 4), но после него оставшиеся $\{4, 7, 8\}$ не покрываются одним подмножеством. К моменту, когда добавлены $S_3$ и $S_2$, подмножество $S_1$ становится лишним: $S_2 \cup S_3 = U$ и без него.

### Поуровневый перебор с отсечением (алгоритм проекта)

Точный алгоритм: покрытия строятся по уровням, от меньшего числа подмножеств к большему. На уровне $k$ находятся все различные объединения, которые нельзя получить меньшим числом подмножеств. Первый уровень, на котором достигнут $J = 1$, даёт минимальное число подмножеств в покрытии.

#### Ключевое свойство метрики

Любое покрытие $K$ — это объединение подмножеств из $S$, поэтому $K \subseteq U$. Тогда $K \cap U = K$ и $K \cup U = U$, и

$$
J(K, U) = \frac{|K|}{|U|}
$$

Добавление подмножества с новыми элементами строго увеличивает $|K|$, а значит и $J$. При этом $J(K, U) = 1$ тогда и только тогда, когда $K = U$.

#### Пример: уровень 1

Каждое подмножество оценивается относительно универсума:

- $J(S_1, U) = \dfrac{|S_1 \cap U|}{|S_1 \cup U|} = \dfrac{5}{8} = 0.625$
- $J(S_2, U) = \dfrac{4}{8} = 0.5$
- $J(S_3, U) = \dfrac{4}{8} = 0.5$

Лучший результат уровня: $J = 0.625$ у $S_1$. Так как $J < 1$, переходим на уровень 2.

#### Пример: уровень 2

К каждому покрытию уровня 1 добавляется подмножество с большим номером. Объединения $S_i \cup S_j$ и $S_j \cup S_i$ совпадают, поэтому рассматриваются только уникальные комбинации. Полученное объединение сравнивается с покрытием из строки: улучшение ($+$) означает, что $J(S_i \cup S_j, U) > J(S_i, U)$.

**Расчёт $J(S_i \cup S_j, U) = |S_i \cup S_j| / |U|$:**

- $J(S_1 \cup S_2, U) = \dfrac{|\{1, 2, 3, 4, 5, 6\}|}{8} = \dfrac{6}{8} = 0.75$
- $J(S_1 \cup S_3, U) = \dfrac{|\{1, 2, 3, 5, 6, 7, 8\}|}{8} = \dfrac{7}{8} = 0.875$
- $J(S_2 \cup S_3, U) = \dfrac{|\{1, 2, 3, 4, 5, 6, 7, 8\}|}{8} = \dfrac{8}{8} = 1$

| Комбинация $C$ | $S_1$ | $S_2$ | $S_3$ |
|----------------|-------|-------|-------|
| $S_1$ |   | $+$ | $+$ |
| $S_2$ |   |   | $+$ |
| $S_3$ |   |   |   |

Ячейка на пересечении строки $S_i$ и столбца $S_j$ показывает, улучшилось ли покрытие: $+$, если $J(S_i \cup S_j, U) > J(S_i, U)$, иначе $-$. Диагональ и всё, что ниже неё, не заполняется. Все три объединения дают улучшение: $0.75 > 0.625$, $0.875 > 0.625$ и $1 > 0.5$.

Лучший результат уровня 2: $J = 1$ у покрытия $\{S_2, S_3\}$. Перебор останавливается, минимальное покрытие состоит из двух подмножеств. Это совпадает с выводом ноутбука:

```text
Уровень: 1, самый высокий коэффициент Жаккара: 0.625
[[1, 2, 3, 5, 6]]
Уровень: 2, самый высокий коэффициент Жаккара: 1.0
[[1, 2, 3, 4], [5, 6, 7, 8]]
```

#### Псевдокод

```text
LEVEL-SEARCH(U, S):

    J(A, B) = |A ∩ B| / |A ∪ B| #коэффициент Жаккара

    combinations = ∅ #покрытия текущего уровня
    for i = 1, ..., m: #уровень 1: каждое подмножество - отдельное покрытие
        if S_i ∉ keys(combinations):
            combinations[S_i] = (i)

    seen = keys(combinations) #все покрытия, найденные на любом уровне
    level = 1

    while true:
        best_score = max J(cover, U) for cover ∈ keys(combinations) #лучший коэффициент Жаккара уровня
        best_comb = {cover ∈ keys(combinations) : J(cover, U) = best_score}
        output level, best_score, {combinations[cover] : cover ∈ best_comb}

        if best_score = 1: #универсум покрыт, level - минимальное число подмножеств
            return level, best_comb

        new_combinations = ∅
        for (cover, combination) in combinations:
            for i = 1, ..., m:
                new_cover = cover ∪ S_i

                if new_cover = cover: #подмножество ничего нового не покрыло
                    continue

                if new_cover ∈ seen: #такое покрытие уже получали: на этом уровне или раньше
                    continue

                seen += {new_cover}
                new_combinations[new_cover] = combination + (i)

        if new_combinations = ∅: #новых покрытий нет, полное покрытие недостижимо
            return level, best_comb

        combinations = new_combinations
        level += 1
```

Отсечение по `seen` не теряет решений: если покрытие уже получено на более раннем уровне, оно собирается меньшим числом подмножеств, и повторно рассматривать его не нужно. Поэтому на каждом уровне в `combinations` остаются только покрытия, которые нельзя собрать меньшим числом подмножеств.

#### Сложность

Число различных покрытий может достигать $2^m$, поэтому в худшем случае алгоритм экспоненциален по $m$. Взамен он гарантированно находит минимальное покрытие, в отличие от жадного алгоритма.

## Использование в реальных задачах

В реальной жизни более распространены примеры, когда нам нужно покрыть какое-либо множество (заданий, площадь фигуры и т.д.) с помощью других множеств, необязательно подмножеств.

Допустим, что выполнение задачи требует определённых навыков: $\{A, B, C, D\}$. Среди сотрудников есть несколько человек, которые владеют этими навыками: $S_1 = \{A, B, C, D, E, F, G\}$, $S_2 = \{A, C\}$, $S_3 = \{B, D\}$. Минимальным покрытием тут будет являться $C = \{S_1\}$, но вместе с тем, оно будет содержать лишние элементы: $\{E, F, G\}$. В реальной жизни мы бы посчитали неоптимальным использование первого сотрудника, т.к. лишние навыки могли быть использованы в дугих задачах. Таким образом, более оптимальным для нас было бы покрытие $C = \{S_2, S_3\}$.
